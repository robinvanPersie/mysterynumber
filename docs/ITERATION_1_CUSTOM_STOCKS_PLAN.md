# 神秘数字第一次功能迭代：手动添加股票

## 1. 迭代目标

在现有“神秘数字”桌面行情程序的基础上，增加手动输入沪深股票数字代码的能力。

用户可以输入 6 位数字代码，将股票添加到行情面板顶部；程序根据代码自动识别上海或深圳市场，拼接腾讯行情接口参数并获取数据。用户添加的股票可以删除，原有四个指数始终保留。

本迭代同时支持：

- Windows Compose Desktop 主程序。
- macOS 原生 SwiftUI 菜单栏面板。

本迭代不改变现有 macOS 菜单栏入口、Windows 普通窗口和系统托盘行为。

## 2. 功能范围

### 2.1 包含内容

- 输入 6 位沪深股票或指数代码。
- 自动识别上海市场和深圳市场。
- 将代码转换为腾讯接口参数，例如 `600519` 转换为 `sh600519`。固定指数继续使用 `s_sh...` 或 `s_sz...` 参数。
- 新添加的股票显示在面板最上方。
- 用户添加的股票支持删除。
- 删除后立即从内存列表、界面和请求地址中移除。
- 禁止添加重复代码。
- 原有四个指数固定存在，不能删除，也不能通过输入框重复添加。
- 面板尺寸保持现有尺寸不变。
- 列表最多同时显示约 4 项，超过后在列表区域内部滚动。
- 固定指数与用户添加的股票一起参与滚动。
- Windows 和 macOS 的功能、顺序、校验和错误提示保持一致。

### 2.2 不包含内容

- 不保存用户添加的股票列表。
- 不增加账号同步或跨设备同步。
- 不支持港股、美股、基金、债券或其他非沪深代码。
- 不增加自选股分组、排序或复杂编辑功能。
- 不改变现有 30 秒自动刷新机制。
- 不改变现有应用名称、图标和平台入口行为。

## 3. 固定指数

以下四项是系统固定数据，始终存在于列表底部：

| 显示名称 | 数字代码 | 腾讯请求参数 | 是否可删除 |
| --- | --- | --- | --- |
| 上证指数 | `000001` | `s_sh000001` | 否 |
| 深证成指 | `399001` | `s_sz399001` | 否 |
| 创业板指 | `399006` | `s_sz399006` | 否 |
| 科创 50 | `000688` | `s_sh000688` | 否 |

固定指数不能通过输入框再次添加。即使用户输入它们的数字代码，也应提示已经存在。

## 4. 列表顺序

面板列表按照以下规则排列：

```text
最新添加的用户股票
较早添加的用户股票
...
上证指数
深证成指
创业板指
科创 50
```

每次新增股票都插入用户股票列表的第一个位置。删除某一项后，其余项目保持原有相对顺序。

固定指数不会因为新增或删除用户股票而改变顺序。

## 5. 市场识别规则

输入值必须是 6 位纯数字。去除首尾空格后进行校验，内部空格、字母、标点和其他字符均视为无效输入。

### 5.1 上海市场

以下前缀识别为上海市场：

```text
600xxx
601xxx
603xxx
605xxx
688xxx
689xxx
```

### 5.2 深圳市场

以下前缀识别为深圳市场：

```text
000xxx
001xxx
002xxx
003xxx
300xxx
301xxx
399xxx
```

### 5.3 固定指数例外

由于 `000001` 可能被一般前缀规则解释为深圳代码，但在本项目中它代表上证指数，因此固定代码必须使用显式映射：

```text
000001 -> sh
000688 -> sh
399001 -> sz
399006 -> sz
```

### 5.4 转换示例

```text
600519 -> sh600519
688001 -> sh688001
000858 -> sz000858
300750 -> sz300750
```

无法识别的代码不应发起网络请求，应在输入区域附近显示明确错误提示。

## 6. 请求地址生成

将当前列表拆分为固定的基础地址和动态参数列表：

```text
基础地址：
https://qt.gtimg.cn/q=
```

最终请求地址由当前列表顺序生成。例如，用户先后添加 `600519` 和 `000858` 时：

```text
https://qt.gtimg.cn/q=sz000858,sh600519,s_sh000001,s_sz399001,s_sz399006,s_sh000688
```

请求参数顺序必须与面板显示顺序一致：

1. 用户添加的股票，最新添加的在前。
2. 四个固定指数按照既有顺序排列。

添加或删除股票后，都必须重新生成完整请求地址。不能继续请求已经被删除的代码。

## 7. 数据模型设计

建议将列表项目抽象为带有来源类型和请求参数的数据项：

```text
MarketItem
  code: String
  market: Market
  requestCode: String
  kind: Fixed | Custom
```

其中：

- `code`：标准化后的 6 位数字代码。
- `market`：`SH` 或 `SZ`。
- `requestCode`：普通股票例如 `sh600519`，固定指数例如 `s_sh000001`。
- `kind`：固定指数或用户添加股票。

状态层建议维护：

```text
fixedItems: List<MarketItem>
customItems: List<MarketItem>
quotes: List<MarketQuote>
inputCode: String
inputError: String?
```

展示列表由以下方式得到：

```text
customItems + fixedItems
```

用户添加和删除都只作用于 `customItems`。固定指数从 `fixedItems` 中读取，避免被误删或误改。

## 8. 重复代码处理

添加前统一执行标准化和重复检查：

1. 去除首尾空格。
2. 校验是否为 6 位数字。
3. 根据固定映射或市场前缀识别市场。
4. 与固定列表和用户列表比较数字代码。
5. 已存在时拒绝添加，不发起网络请求。

以下输入应视为同一个代码：

```text
600519
 600519
```

重复时提示：

```text
该股票已经添加
```

## 9. Windows UI 方案

Windows 继续使用现有 Compose UI，面板整体尺寸不变。

建议在标题区域下方加入紧凑的输入行：

```text
[ 输入 6 位代码                         ] [+]
```

交互要求：

- 输入框支持键盘输入。
- 点击加号提交。
- 输入框中按 Enter 也可以提交。
- 添加成功后清空输入框。
- 添加失败时保留输入内容，显示错误提示。
- 不要因为错误提示或列表变长而改变窗口尺寸。

用户股票行显示删除按钮，固定指数行不显示删除按钮：

```text
贵州茅台       1450.00       [删除]
上证指数       3696.39
```

列表区域使用固定可用高度的 `LazyColumn`：

- 默认视口显示约 4 项。
- 超出可见范围后仅列表内部滚动。
- 输入区域、更新时间和底部操作区域保持固定。
- 固定指数跟随列表滚动，不固定在窗口底部。

## 10. macOS UI 方案

macOS 继续使用独立原生 SwiftUI `MenuBarExtra(.window)`，不改回 Compose/AWT。

需要在现有 SwiftUI 面板中增加与 Windows 一致的功能：

- 紧凑代码输入区域和添加按钮。
- 用户股票位于固定指数之前。
- 用户股票显示删除按钮。
- 固定指数不显示删除按钮。
- 超过可见数量后使用 SwiftUI `ScrollView` 或 `List` 在面板内部滚动。
- 面板整体尺寸保持当前尺寸。
- 点击外部自动收起的菜单栏行为保持不变。

macOS 的请求和解析逻辑必须与 Windows 使用相同的市场识别规则和请求参数顺序。

## 11. 错误状态

至少覆盖以下情况：

| 场景 | 处理方式 |
| --- | --- |
| 输入为空 | 提示请输入 6 位代码 |
| 长度不是 6 位 | 提示请输入 6 位数字代码 |
| 包含非数字字符 | 提示代码格式不正确 |
| 无法识别市场 | 提示暂不支持该代码 |
| 已存在于固定列表 | 提示该股票已经添加 |
| 已存在于用户列表 | 提示该股票已经添加 |
| 添加后请求失败 | 保留列表项，显示网络错误和上一次有效数据 |
| 删除后重新请求失败 | 删除仍然生效，显示剩余项目的错误状态 |
| 响应中缺少新增代码 | 保留该项目并显示暂无行情，不影响其他项目 |
| 输入过程中网络不可用 | 不阻止输入，提交后再发起请求 |

## 12. 代码改动范围

### Windows / Kotlin

预计涉及：

- `shared/src/commonMain/kotlin/com/mysterynumbers/market/MarketDashboard.kt`
- `shared/src/commonMain/kotlin/com/mysterynumbers/market/MarketViewModel.kt`
- 共享行情模型和请求参数生成逻辑。
- `desktopApp/src/jvmMain/kotlin/com/mysterynumbers/NetworkMarketRepository.kt`
- 必要时补充 Kotlin 的市场识别和接口请求测试。

### macOS / SwiftUI

预计涉及：

- `macosApp/main.swift`
- `macosApp/MarketData.swift`
- macOS 独立的输入状态、列表状态、市场识别和动态请求逻辑。

两端可以分别实现平台 UI，但不能各自定义不同的业务规则。市场识别、固定代码、重复判断和列表顺序必须保持一致。

## 13. 测试计划

### 13.1 代码识别测试

至少验证：

```text
600519 -> sh600519
688001 -> sh688001
000858 -> sz000858
300750 -> sz300750
000001 -> s_sh000001
000688 -> s_sh000688
399001 -> s_sz399001
399006 -> s_sz399006
```

同时验证非法代码、重复代码和不支持代码。

### 13.2 列表行为测试

- 启动时只有四个固定指数。
- 添加一个股票后，它出现在最顶部。
- 连续添加多个股票时，最新的位于最顶部。
- 添加固定指数被拒绝。
- 添加相同用户股票被拒绝。
- 删除用户股票后，该项从界面和请求地址中消失。
- 删除不会影响四个固定指数。
- 添加超过 4 项后，窗口尺寸不变，列表可以滚动。
- 固定指数会跟随列表一起滚动。
- 退出并重新启动后，用户股票恢复为空列表。

### 13.3 双端验证

Windows 重点验证：

- 输入框、加号和删除按钮可用。
- 普通窗口尺寸不变。
- 点击其他窗口时 Windows 主窗口保持显示。
- 系统托盘行为不受影响。

macOS 重点验证：

- 菜单栏左键打开面板。
- 点击面板外部自动收起。
- 输入、添加、删除和滚动可用。
- 不出现 Dock 图标或普通主窗口。
